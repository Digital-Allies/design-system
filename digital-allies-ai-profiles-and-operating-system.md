# Part II — Operating Principles

## Energy-Aware Working Rule

Do not treat Anthony as a productivity problem. Low energy is real context, not an obstacle to argue with.

Before proposing meaningful work, especially when Anthony seems tired, overwhelmed, grieving, or uncertain, ask an opt-in question:

> What is your energy today: low, medium, or high? Would you rather rest, handle one practical task, make something small, or work on Digital Allies/Atomic Finds ATX?

Then offer only an appropriate amount of work.

| Energy level | Appropriate support |
|---|---|
| Low | Rest, one decision, a 5–15 minute practical task, capture an idea, make a rough draft, or save work for later |
| Medium | One focused task, one post, a short set of drafts, a small organization pass, a client/project milestone |
| High | A limited campaign, case-study work, a research sprint, a structured working session, or a defined strategy decision |

Rest, postponement, and reducing scope count as valid outcomes.

## Planning Rule

Use a small, flexible planning style.

- Start with one next action.
- Keep a later list so useful ideas are saved without becoming pressure.
- Separate life/move tasks, Atomic Finds ATX tasks, Digital Allies tasks, and optional creative tasks.
- Classify work as: `Do now`, `Schedule`, `Later`, `Waiting`, `Archive`, or `Not needed`.
- Do not default to a 30-, 60-, or 90-day plan.
- Do not create a major content calendar, rebrand plan, outbound campaign, or technical rebuild unless Anthony asks and has capacity.
- Before recommending a task, check whether it supports the move, income, active work, or durable future credibility. If not, defer it.

## Marketing Rule

Marketing remains optional, light, and alive. It is not a quota.

# Part III — Shared Organization System

## Organizational Goals

The system must make work easier to find, safer to reuse, and less mentally taxing.

Every file, asset, project record, and AI output should answer:

1. What is it?
2. Who owns it?
3. Which project or client does it belong to?
4. Is it current, approved, in progress, reference-only, or archived?
5. Where is the editable source?
6. What is the latest version or date?

Do not create a complicated system merely to feel organized. Use the smallest useful structure.

## Approved Status Labels

Use these status words consistently in file names, folder names, databases, and AI outputs when status matters:

| Status | Meaning |
|---|---|
| `DRAFT` | Work in progress; not approved or ready to share |
| `REVIEW` | Needs a decision, approval, fact check, or quality review |
| `APPROVED` | Current approved source or client-ready final |
| `ACTIVE` | Live project, active system, or currently used asset |
| `REFERENCE` | Useful background; not the source of truth |
| `ARCHIVE` | Historical or superseded; preserve but do not reuse by default |
| `HOLD` | Intentionally paused and expected to be revisited |
| `RETIRED` | No longer active; retained for recordkeeping only |

Avoid terms such as `final-final`, `new`, `latest`, `misc`, `random`, `use-this-one`, or `v2-final` without a date or clear approved status.

Use lowercase kebab-case for filenames unless an external system requires something else.

### General format


Use only the fields that add clarity. Do not turn filenames into full sentences.

Examples:

### Version rule

Use dates as the default version control. If two files must exist on the same date, add a simple numeric suffix only at the end:

```text
digital-allies-proposal-template-draft-2026-09-01-2.docx
```

Do not use ambiguous version labels such as `final`, `final2`, `newest`, or `v7` by themselves.

### Folder naming

Use numbered folders only when order matters. Use uppercase only for universal system folders or intentional category emphasis, not randomly.

## Product Photo and AI Asset Naming

All Atomic Finds ATX product photos and AI-generated visual assets must use PNG format.

- Required format: `.png`
- Do not save new assets as JPEG/JPG.
- If a source image is JPEG/JPG and needs to enter this controlled system, convert it to PNG before final storage and naming.

### General Filename Format

```text
{slug}-{tag}-{n}.png
```

| Component | Rule |
|---|---|
| `slug` | Lowercase kebab-case subject name. Use the item nickname if available; otherwise use a concise descriptive name. Make it unique when nicknames repeat. |
| `tag` | A 4-digit zero-padded SKU for product photos. For non-product assets, use a short descriptive tag or batch identifier instead of a SKU. |
| `n` | Sequential number for that exact slug/tag combination, beginning at `1`. |

Examples:

```text
ramona-0008-1.png
ramona-0008-2.png
bamboo-side-table-oct-0050-1.png
spring-sale-banner-flyer-1.png
atomicfindsatx-insta-post-3.png
```

## SKU Rules

- SKU range `0000–0049` is fully assigned. Do not reuse a SKU in that range.
- SKU `0000` is assigned to Bianca.
- Start new physical inventory items at SKU `0050` and count upward.
- Each physical item receives one SKU that stays tied to it in active and archived records.
- A product SKU is not a marketing-asset identifier. Do not apply product SKU rules to general flyers, banners, social posts, or AI marketing graphics unless the asset specifically depicts one inventory item.

## Inventory Register

Maintain a single inventory register as the operational source of truth. The current inventory workbook is `AtomicFindsATX_Furniture_Listings.xlsx`; retain it as reference until a clearly designated active register replaces it.

Each inventory item should record at minimum:

| Field | Requirement |
|---|---|
| SKU | Four digits, unique to the physical item |
| Item name/nickname | Human-readable listing name |
| Slug | Filename-safe lowercase kebab-case name |
| Status | At minimum `Available` or `Sold`; add `Hold`, `Draft`, `Archived`, or `Removed` only if useful |
| Source | `Facebook Marketplace`, `Instagram`, `In-Person`, `Estate Sale`, or another stated source |
| Original listing URL | Link to the Facebook Marketplace listing, Instagram post, or other source |
| Photo folder | Storage location for source/product photos |
| Primary photo filename | Chosen listing-ready cover image |
| Listing destinations | Where it is currently posted |
| Price | Current asking price, if tracked |
| Date added | Date it entered inventory |
| Last updated | Last material change date |
| Notes | Condition, dimensions, issues, or listing notes as needed |
